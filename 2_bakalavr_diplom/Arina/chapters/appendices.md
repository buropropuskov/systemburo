# Приложение А

Полный перечень функциональных требований к системе Dockee

Требования собраны из спецификаций команды разработки: серверная часть (Батютдинов А.Э.) и клиентская часть (Мякотных С.М.). Формулировки приведены в формате «функция для достижения цели».

Таблица А.1 -- Функциональные требования к системе Dockee

| ID | Группа | Требование (функция → цель) | Источник |
|----|--------|----------------------------|----------|
| ФС-01 | Аутентификация | Регистрация по email и паролю для создания учётной записи и доступа к сервису | Бэкенд |
| ФС-02 | Аутентификация | Вход с выдачей пары JWT-токенов (access 15 мин + refresh 7 дней) для безопасного сеансового доступа | Бэкенд |
| ФС-03 | Аутентификация | Автоматическое обновление access-токена через refresh для бесшовной работы без повторного ввода пароля | Бэкенд |
| ФС-04 | Аутентификация | Выход из системы с инвалидацией refresh-токена для предотвращения несанкционированного доступа | Бэкенд |
| ФС-05 | Профиль | Просмотр и редактирование данных профиля (имя, email, аватар) для актуализации контактной информации | Фронтенд |

| ФС-15 | Документы | Удаление и переименование документов с диалогом подтверждения для предотвращения случайной потери | Фронтенд |
