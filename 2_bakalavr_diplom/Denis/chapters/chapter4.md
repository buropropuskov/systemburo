## 4.2 Ключевые фрагменты реализации

### 4.2.1 Ядро сравнения

Метод `analyser::run_for_cm()` — точка входа во весь цикл анализа. На вход он принимает идентификатор `course module` (cmid), забирает закэшированный текст по всем студентам из таблицы `plagiarism_samost_files`, делит контент каждого пользователя на два «ведра» — код и текст, затем генерирует все пары и для каждой пары вызывает либо Winnowing (код), либо Жаккара (текст). Результаты пишутся в `plagiarism_samost_results`. Ниже приведён центральный фрагмент.

*Листинг 4.1 — Метод сравнения пары работ (фрагмент `classes/analyser.php`)*

```php
public function run_for_cm(int $cmid): int {
    global $DB;

    $records = $DB->get_records('plagiarism_samost_files', ['cm' => $cmid]);
    $buckets = [];
    foreach ($records as $rec) {
        if (empty($rec->textcontent)) { continue; }
        $uid = $rec->userid;
        $blocks = self::split_combined_content((string)$rec->textcontent);
        foreach ($blocks as $block) {
            $payload = text_extractor::payload($block);
            if (text_extractor::is_code($block)) {
                $buckets[$uid]['code'] .= "\n\n" . $payload;
            } else {
                $buckets[$uid]['text'] .= ' ' . $payload;
            }
        }
    }
    $userids = array_keys($buckets);
    $n = count($userids);
    if ($n < 2) { return 0; }

    $DB->delete_records('plagiarism_samost_results', ['cm' => $cmid]);
    $pairs_done = 0; $now = time();
    for ($i = 0; $i < $n; $i++) {
        for ($j = $i + 1; $j < $n; $j++) {
            $u1 = $userids[$i]; $u2 = $userids[$j];
            $sim_code = null;
            if ($buckets[$u1]['code'] !== '' && $buckets[$u2]['code'] !== '') {
                $sim_code = round($this->winnowing_similarity(
                    $buckets[$u1]['code'], $buckets[$u2]['code']) * 100, 2);
            }
            $sim_text = null;
            if ($buckets[$u1]['text'] !== '' && $buckets[$u2]['text'] !== '') {
                $sim_text = round($this->jaccard_similarity(
                    $buckets[$u1]['text'], $buckets[$u2]['text']) * 100, 2);
            }
            $DB->insert_record('plagiarism_samost_results', (object)[
                'cm' => $cmid, 'userid1' => $u1, 'userid2' => $u2,
                'similarity_code' => $sim_code, 'similarity_text' => $sim_text,
                'timecalculated' => $now,
            ]);
            $pairs_done++;
        }
    }
    return $pairs_done;
}
```

Логика вписывается в Plugin API [11] прозрачно: задача `process_queue` вызывает метод из cron-контекста, без блокировки web-потока. Отдельного внимания заслуживает `split_combined_content()` — он читает префиксы `CODE:` и `TEXT:` (константы `TYPE_CODE`, `TYPE_TEXT` в `text_extractor`) и разбивает смешанные сдачи, где студент приложил архив с кодом и пояснительную записку. В версии расширенного охвата (`run_for_cm_with_scope`) реализованы ещё режимы `within` и `cross` — сравнение внутри группы и против внешнего набора пользователей; это пригодится, например, чтобы проверить новый поток против прошлогоднего.

### 4.2.2 Извлечение текста из DOCX

DOCX-файл устроен как ZIP-архив; тело документа лежит в `word/document.xml`, а текст разметки XML завёрнут в элементы `<w:t>` пространства имён `...wordprocessingml/2006/main`. Мы намеренно отказались от тяжеловесной PhpWord [21] в пользу лёгкого парсинга через `ZipArchive` и `DOMDocument`: PhpWord тянет зависимостей на десятки мегабайт, а плагин должен оставаться компактным по требованию Moodle Coding Style [16]. Fallback на PhpWord держится в запасе на случай экзотических файлов с embedded-объектами.

*Листинг 4.2 — Извлечение текста из DOCX (`classes/text_extractor.php`)*

```php
private static function extract_docx(\stored_file $file): string {
    $tmp = make_request_directory() . '/' . clean_filename($file->get_filename());
    $file->copy_content_to($tmp);

    $zip = new \ZipArchive();
    if ($zip->open($tmp) !== true) {
        @unlink($tmp);
        return '';
    }
    $xml = $zip->getFromName('word/document.xml');
    $zip->close();
    @unlink($tmp);
    if ($xml === false) { return ''; }

    libxml_use_internal_errors(true);
    $dom = new \DOMDocument();
    $dom->loadXML($xml);
    libxml_clear_errors();

    $texts = [];
    $nodes = $dom->getElementsByTagNameNS(
        'http://schemas.openxmlformats.org/wordprocessingml/2006/main', 't'
    );
    foreach ($nodes as $node) {
        $texts[] = $node->nodeValue;
    }
    return self::normalise(implode(' ', $texts));
}
```

Кросс-форматный подход реализован единообразно: `extract()` сначала классифицирует файл через `file_types::classify()`, затем вызывает специализированный метод. DOCX идёт через `extract_docx()`, PDF — через `extract_pdf()` (под капотом shell-вызов `pdftotext`, альтернатива Smalot PdfParser [28]), XLSX планируется переключить на PhpSpreadsheet [30]. ZIP обрабатывается рекурсивно в `extract_zip()`, где каждый внутренний файл классифицируется заново и игнорируются служебные пути (`.git`, `node_modules`, `vendor` — см. `file_types::ARCHIVE_SKIP_PATTERNS`).

### 4.2.3 Реализация Winnowing

Оригинальный алгоритм Schleimer [9] на PHP 8.1 [31] собран строго по спецификации: токены → k-граммы → хеши → скользящее окно → минимумы. Мы выбрали `crc32` вместо более тяжёлого MD5 осознанно: длины хеша хватает для k=5, а производительность выше в 3-4 раза (проверялось на тестовом стенде).

*Листинг 4.3 — Реализация Winnowing (`classes/text_extractor.php`)*

```php
public static function winnowing_fingerprints(
    string $token_stream,
    int $k = 5,
    int $w = 4
): array {
    $tokens = preg_split('/\s+/u', $token_stream, -1, PREG_SPLIT_NO_EMPTY);
    $n = count($tokens);
    if ($n < $k) {
        return [crc32($token_stream) => true];
    }
    $hashes = [];
    for ($i = 0; $i <= $n - $k; $i++) {
        $kgram = implode(' ', array_slice($tokens, $i, $k));
        $hashes[] = crc32($kgram);
    }
    $m = count($hashes);
    if ($m < $w) {
        return array_fill_keys($hashes, true);
    }
    $fingerprints = [];
    $prev_min_pos = -1;
    for ($i = 0; $i <= $m - $w; $i++) {
        $min_pos = $i;
        for ($j = $i + 1; $j < $i + $w; $j++) {
            if ($hashes[$j] < $hashes[$min_pos]) {
                $min_pos = $j;
            }
        }
        if ($min_pos !== $prev_min_pos) {
            $fingerprints[$hashes[$min_pos]] = true;
            $prev_min_pos = $min_pos;
        }
    }
    return $fingerprints;
}
```

Параметры `k=5`, `w=4` обоснованы в главе 3 (баланс между устойчивостью к перестановкам строк и чувствительностью к коротким совпадениям). Сами токены готовит `tokenise_code()`: снимает комментарии, заменяет строковые литералы на `STR`, числа на `NUM`, переменные — на `VAR`, а ключевые слова 30+ языков оставляет как есть. Благодаря этому плагин устойчив к типовым уловкам — переименованию идентификаторов, смене форматирования, изменению строковых констант.

### 4.2.4 Фоновая обработка очереди

Moodle запускает наш класс `plagiarism_samost\task\process_queue` через подсистему cron, зарегистрированную в `db/tasks.php`. Задача помечена `minute='*'`, то есть попытка разбора очереди предпринимается раз в минуту — если очередь пуста, метод `execute()` возвращается за 2-3 мс. Пачка — не более 100 записей, что защищает от долгой нагрузки на общий cron Moodle.

*Листинг 4.4 — Фоновая задача очереди (`classes/task/process_queue.php`)*

```php
public function execute(): void {
    global $DB, $CFG;
    $batch_size = 100;
    require_once($CFG->dirroot . '/mod/assign/locallib.php');

    $rows = $DB->get_records_select(
        'plagiarism_samost_queue',
        "status = 'queued'", [], 'timecreated ASC', '*', 0, $batch_size
    );
    if (empty($rows)) {
        mtrace('plagiarism_samost: queue is empty, nothing to do.');
        return;
    }
    $by_cm = [];
    foreach ($rows as $row) { $by_cm[$row->cm][] = $row; }

    $shingle_size = (int)(get_config('plagiarism_samost', 'shingle_size') ?: 7);
    $fs = get_file_storage();

    foreach ($by_cm as $cmid => $cm_rows) {
        $row_ids = array_column($cm_rows, 'id');
        [$in_sql, $in_params] = $DB->get_in_or_equal($row_ids);
        $DB->execute("UPDATE {plagiarism_samost_queue}
             SET status='processing', timemodified=? WHERE id $in_sql",
             array_merge([time()], $in_params));
        try {
            $anal = new analyser($shingle_size);
            // извлекаем текст, запускаем сравнение...
            $anal->run_for_cm_with_scope((int)$cmid, $userids_to_process,
                $scope_mode, $scope_compare_ids);
            $DB->execute("UPDATE {plagiarism_samost_queue}
                SET status='done', timemodified=? WHERE id $in_sql",
                array_merge([time()], $in_params));
        } catch (\Throwable $e) {
            $DB->execute("UPDATE {plagiarism_samost_queue}
                SET status='error', timemodified=? WHERE id $in_sql",
                array_merge([time()], $in_params));
            mtrace("  cm={$cmid}: ERROR — " . $e->getMessage());
        }
    }
}
```

Отказоустойчивость реализована через явный state-machine статусов в `plagiarism_samost_queue`: `queued → processing → done | error`. Любой `Throwable` перехватывается и пачка получает статус `error` — но уже сохранённые в `plagiarism_samost_results` пары остаются валидными. Такой подход безопаснее «тихих» сбоев: администратор видит ошибку в `mtrace` и может разобрать конкретный cm вручную.

## 4.3 Развёртывание и установка

Плагин разворачивается пятью шагами:

1. Копирование каталога `samost/` в `moodle/plagiarism/` на сервере.
2. Вход в админку Moodle, раздел «Site administration → Notifications». Moodle замечает новый компонент `plagiarism_samost`, запускает `db/install.php` и создаёт пять таблиц по схеме `install.xml`: `plagiarism_samost_files`, `_results`, `_config`, `_queue`, `_feedback`.
3. Включение типа plagiarism на уровне сайта: «Site administration → Advanced features → Enable plagiarism plugins».
4. Активация плагина: «Plugins → Plagiarism plugins → Manage plagiarism plugins → samost».
5. Глобальные настройки: «Plagiarism plugins → Samost settings», где задаются порог срабатывания (по умолчанию 70%) и размер шингла (по умолчанию 7).

Рисунок 4.1 показывает административную форму с настройками — порогами, размером шингла и флагом `enabled`. Все элементы построены на стандартных `moodleform` [11]; HTML-разметка отрисовывается через встроенный Mustache-рендерер [22], поэтому внешне форма ничем не отличается от штатных форм Moodle.

После включения плагин становится доступен в настройках каждого задания. Преподаватель открывает «Edit assignment → Plagiarism samost», ставит флажок `samost_use` и сохраняет. Рисунок 4.2 демонстрирует эту часть интерфейса. С момента сохранения плагин подписывается на события `assessable_uploaded` и `assessable_submitted`, после каждой сдачи добавляет строку в `plagiarism_samost_queue`, и в течение минуты очередь подхватывает её.

## 4.4 Тестирование

### 4.4.1 Модульное тестирование (PHPUnit)

Для Moodle-плагинов стандартом является PHPUnit [32], интегрированный в ядро через `admin/tool/phpunit/` [33]. Инициализация окружения запускается один раз: `php admin/tool/phpunit/cli/init.php`, после чего тесты гоняются командой `vendor/bin/phpunit plagiarism/samost/tests/`. Мы следовали рекомендациям Куликова [34] о пирамиде тестов: большинство случаев закрываем быстрыми unit-тестами, интеграционные добавляем на ключевых сценариях.

Написано 29 unit-тестов, сгруппированных по трём классам.

Класс `analyser_test.php` (12 тестов). Проверяется, что `jaccard_similarity` возвращает число в диапазоне [35, 36]; идентичные тексты дают 1.0, а полностью разные — значение ниже 0.05; замена порядка слов влияет на метрику (корректность шинглов); `winnowing_similarity` на равных потоках токенов выдаёт 1.0, а при частичной подстановке `VAR`-ов — промежуточные значения 0.3–0.7. Отдельно протестирован `split_combined_content()`: смешанный контент с префиксами `CODE:` и `TEXT:` разбивается на два блока без потерь.

Класс `text_extractor_test.php` (10 тестов). Покрывает разбор DOCX, PDF, ZIP и токенизацию кода. Самый полезный тест — `test_tokenise_code_strips_comments_py_java_php_cpp`: он подаёт на вход четыре эталонных сниппета с одинаковой логикой и разными стилями комментариев, ожидает одинаковый токен-поток на выходе. Второй критичный — `test_extract_pdf_returns_empty_on_scan`: если `pdftotext` не смог извлечь текстовый слой (например, скан), возвращается пустая строка, а не исключение.

Класс `queue_test.php` (7 тестов). Проверяется переход статусов `queued → processing`, корректная запись `timemodified`, логика группировки по cm, поведение при пустой очереди (метод возвращается без ошибок). Отдельный тест имитирует `\Throwable` внутри `run_for_cm_with_scope` и ожидает, что все строки пачки получат `status='error'`, а не `done`.

Рисунок 4.3 показывает вывод PHPUnit: 29 тестов, 0 ошибок, время прогона 3.2 секунды. Покрытие по `phpunit --coverage-text` — 58% по строкам и 71% по методам (ниже 80% — но основные развилки алгоритмов закрыты; оставшиеся непокрытые ветки — это обработка экзотических MIME-типов, для которых проще тестировать вручную).

### 4.4.2 Интеграционное тестирование

Сценарии разрабатывались по методологии Куликова [34]: каждый сценарий — законченный путь пользователя от начала до получения результата.

Сценарий 1 — полный цикл на группе 5 студентов. Шаги: (1) создать тестовый курс; (2) создать задание с включённым samost_use; (3) зарегистрировать 5 учётных записей-студентов; (4) загрузить от каждого по одной работе — два DOCX с явным заимствованием 80%, три независимых; (5) дождаться, пока cron разберёт очередь (до 60 секунд); (6) открыть `report.php` и проверить, что сгенерировалось C(5, 2) = 10 пар; (7) проверить, что 1 пара помечена красным (high, ≥60%), одна — жёлтым (mid, 20-60%), остальные — зелёным (low); (8) зайти на `pair.php` для красной пары, убедиться в подсветке совпадений.

Сценарий 2 — обработка мусорного PDF. Загружаем PDF, состоящий из отсканированных страниц без текстового слоя. Ожидание: метод `extract_pdf_from_path()` возвращает пустую строку, `cache_file()` пропускает файл без записи в `plagiarism_samost_files`. Пара с этим пользователем не создаётся, остальные пары считаются штатно. Факт пропуска отображается на UI меткой «нет текста для анализа».

Сценарий 3 — масштабирование до 30 студентов (C(30, 2) = 435 пар). Каждый студент сдал DOCX объёмом 2-3 страницы плюс ZIP с кодом из 5-7 файлов на Python. Замеряли время работы `process_queue::execute()`, пиковое потребление RAM процессом `php cli/cron.php`, нагрузку на CPU.

В процессе прогонов обнаружили три дефекта, которых не поймал PHPUnit. Первый — первая версия `extract_docx()` падала на DOCX с embedded OLE-объектами, так как `DOMDocument::loadXML` выбрасывал предупреждение; исправили добавлением `libxml_use_internal_errors(true)` (см. Листинг 4.2). Второй — при очень большом архиве (>50 МБ) PHP упирался в `memory_limit=128M`; добавили проверку размера в `extract_zip()` и документировали требование не менее 256 МБ. Третий — при совпадающих шаблонных титульниках (те же 5-6 строк «МИРЭА, кафедра, группа») Жаккар давал ложные 25-30%; решили через тюнинг `shingle_size` на 7 вместо 5 для задач с короткими работами.

### 4.4.3 Ручное UI-тестирование

Проверяли интерфейс на трёх разрешениях — 1920×1080, 1366×768, 1024×768. Все ключевые элементы (таблица пар, модалки, панели фильтров) корректно перестраиваются благодаря сеткам Bootstrap 5 [26]. Клик по ячейке пары открывает модальное окно с полными работами и подсветкой совпадающих шинглов (`<mark class="similarity-high">`). Экспорт CSV через кнопку «Export» отдаёт файл в UTF-8 с BOM-маркером — Excel корректно открывает кириллицу без шаманства с кодировкой. Локализация проверена на двух языковых пакетах: `lang/ru/plagiarism_samost.php` и `lang/en/plagiarism_samost.php` — все строки `get_string()` имеют пары, непереведённых маркеров не найдено.

## 4.5 Оценка эффективности снижения трудозатрат

Ключевой вопрос ВКР — насколько плагин снижает время преподавателя. За базу взята оценка Коваленко [7]: медианное время беглого попарного визуального сравнения двух студенческих работ объёмом 1-2 страницы составляет 1,5 минуты. Цифра консервативная — опытные преподаватели часто укладываются в минуту, начинающие могут тратить 2-3. Берём середину.

Формула проверки «все против всех» даёт число пар как биномиальный коэффициент C(N, 2) = N·(N-1)/2, где N — размер группы. Соответствующие замеры сведены в Таблицу 4.3.

*Таблица 4.3 — Сравнение трудозатрат преподавателя*

| Размер группы | Пар C(N, 2) | Ручная проверка | С плагином | Экономия |
|---------------|-------------|-----------------|------------|----------|
| 15 | 105 | 2 ч 37 мин | 7 мин | ×22 |
| 25 | 300 | 7 ч 30 мин | 15 мин | ×30 |
| 30 | 435 | 10 ч 53 мин | 20 мин | ×32 |
| 50 | 1 225 | 30 ч 37 мин | 45 мин | ×40 |

Для типового случая «группа 25 человек» снижение с 7,5 часов до 15 минут означает качественный сдвиг: вместо выборочной проверки пары случайных работ преподаватель охватывает все задания курса. В педагогическом смысле это важнее пропорции экономии — Рыбаков [18] отмечает, что именно невозможность сплошной проверки порождает у студентов ощущение безнаказанности при списывании. Плагин устраняет этот барьер.

Второй критерий — точность алгоритмов. Собран синтетический датасет из 50 студенческих работ. 30 работ уникальны (взяты из репозитория прошлогодних ВКР-проектов кафедры, без повторов). 20 — подготовлены как намеренный плагиат: 12 с прямым копированием текста с косметической заменой формулировок, 5 с переименованием переменных в коде на Python, 3 с частичным заимствованием (15-25% объёма). Пороги выставлены по умолчанию: текст ≥ 40%, код ≥ 35%. Результаты.

Recall = 18 / 20 = 90%. Плагин пропустил 2 пары, обе — из категории частичного заимствования (15-25% объёма), что ниже заданного порога. Это управляемая характеристика: при пороге 25% плагин ловит все 20, но вместе с этим растёт precision-проблема.

Precision = 18 / 19 = 95%. Одно ложное срабатывание: у двух студентов совпал шаблонный титульник на 5-6 строк, что при `shingle_size=5` и коротких работах (~2 страницы) дало Жаккара 42%. Решение: либо увеличить `shingle_size`, либо вести whitelist шаблонных фрагментов (направление на доработку).

F1-score = 2 · P · R / (P + R) = 2 · 0.95 · 0.90 / 1.85 = 0.925. Результат сопоставим с публикациями по классическим методам без ML [13], [6], [15] — типовой диапазон для shingles + Winnowing. Практический вывод: алгоритмы применимы для текущего контроля в рамках курса. Критические решения (дисциплинарные санкции) по-прежнему должен принимать преподаватель, но плагин резко сокращает поле для ручной проверки.

## 4.7 Перспективы развития

Пять направлений доработки были выделены по итогам тестирования и обратной связи.

Первое — переход от шинглов к семантическим эмбеддингам. Современные модели типа SBERT [37], [38], [39] ловят перефразирование, которое классический Жаккар пропускает: смена формулировок без сохранения дословных 5-грамм даёт Жаккара близкого к нулю, тогда как косинусная близость эмбеддингов остаётся 0.8-0.9. Интеграция потребует прослойки на Python и REST-вызова из PHP.

Второе — поддержка OCR для PNG/JPG через tesseract. Часть дисциплин (математика, физика) получает от студентов рукописные решения в виде фотографий — сейчас они попадают в категорию `unknown` и не анализируются. OCR + нормализация формул покроют этот кейс.

Третье — опциональная кросс-проверка с внешним сервисом Антиплагиат [3]. Наш плагин сравнивает только работы в рамках одной группы; для выпускных квалификационных работ требуется проверка против веб-базы, которую собственными силами не поднять.

Четвёртое — агрегированная админская панель «курс с наиболее подозрительной активностью»: сортировка курсов по доле пар выше порога, тренды по семестрам. Это позволит замдекану точечно вмешиваться, не просматривая каждый курс вручную.

Пятое — адаптация под Moodle Workplace (корпоративную версию). Для корпоративных заказчиков с обучением сотрудников поддержка ролевой модели Workplace и кастомных learning paths — обязательное требование для серьёзного внедрения [15].

## Выводы по главе 4

Решена задача 4 — реализация, тестирование и оценка эффективности.

Реализован плагин типа `plagiarism` на PHP 8.1 [31]: 22 PHP-файла, 4 362 строки PHP, 950 строк CSS, 220 строк локализации. Структура соответствует Plugin API Moodle [11] и Coding Style [16]: неймспейс `plagiarism_samost\`, разделение `classes/` и `tabs/`, миграции в `db/install.xml` (пять таблиц).

Ядро сравнения (`analyser.php`) реализует два алгоритма: Жаккар на шинглах [8] для текста и Winnowing [9] для кода. Токенизация 30+ языков программирования с нормализацией идентификаторов в `text_extractor::tokenise_code()` делает плагин устойчивым к типовым уловкам.

Написано 29 unit-тестов в трёх классах с покрытием 58% по строкам, прогнано 3 сценария интеграционного тестирования — все зелёные. По итогам тестов исправлены три дефекта, которые PHPUnit не поймал.

Оценка эффективности на синтетическом датасете 50 работ: recall 90%, precision 95%, F1 = 0.925. Трудозатраты преподавателя снижаются в 22-40 раз в зависимости от размера группы: для группы 25 человек с 7,5 часов до 15 минут.

Определены пять направлений развития: семантические эмбеддинги [37], [38], [39], OCR, кросс-проверка с Антиплагиат [3], агрегированные метрики администратора, адаптация под Moodle Workplace.
