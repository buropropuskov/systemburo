# ЗАКЛЮЧЕНИЕ

В рамках выпускной квалификационной работы решены все четыре задачи, поставленные в задании, и достигнута цель — повышение эффективности процесса оценивания степени самостоятельности решения задач студентами за счёт снижения трудозатрат преподавателя на проверку заданий текущего контроля.

Анализ существующих инструментов показал, что ни один из четырёх рассмотренных сервисов — Turnitin, «Антиплагиат», MOSS, JPlag — не закрывает задачу полностью. Коммерческие платформы [2], [3] ориентированы на сравнение с внешней базой и требуют передачи данных в зарубежное облако, что для российского вуза несовместимо с требованиями ФЗ-152. Свободные инструменты [4], [5] работают исключительно с исходным кодом, без интеграции с LMS. По итогам обзора сформулированы десять функциональных и восемь нефункциональных требований к плагину, определены целевые метрики (время обработки пары не более трёх секунд, обработка группы 30 студентов за 10 минут, покрытие тестами не ниже 50 процентов).

Моделирование предметной области выявило ключевую болевую точку: попарное ручное сравнение работ в группе из 25 студентов занимает около 7,5 часов только на одно задание [7]. Построены диаграммы бизнес-процессов «как есть» и «как будет» в нотации BPMN, разработаны карта пользовательских историй из восьми позиций и диаграмма вариантов использования в нотации UML [20]. Выделены три роли: преподаватель, студент, администратор Moodle, — каждая с собственным набором сценариев. Предложенная модель «как будет» показала потенциальную экономию порядка 30× по времени преподавателя.

В главе проектирования обоснована архитектура плагина типа `plagiarism` для Moodle Plugin API [10], [11]: три слоя (интерфейс, обработка, анализ), паттерны Strategy и Observer [24], [25]. Спроектирована схема базы данных из пяти собственных таблиц с префиксом `plagiarism_samost_`. Для текста выбран метод шинглов с коэффициентом Жаккара (k=5–7) [8], для исходного кода — алгоритм Winnowing (k=5, w=4) [9]. Обработка форматов распределена по специализированным библиотекам: PhpWord [21] для DOCX, Smalot PdfParser [28] для PDF, PhpSpreadsheet [30] для XLSX.

Реализация дала рабочий плагин объёмом 22 PHP-файла, 4 362 строки PHP-кода и 950 строк CSS, соответствующий Moodle Coding Style [16]. Написано 29 модульных тестов в PHPUnit [32], [33] и проведены три сценария интеграционного тестирования, все пройдены. Измерения на синтетическом датасете из 50 работ показали recall 90 процентов, precision 95 процентов, F1-меру 0,925. Количественная оценка эффективности подтвердила снижение трудозатрат преподавателя в 22–40 раз в зависимости от размера группы: для типовой группы 25 человек проверка одного задания сокращается с 7,5 часов до 15 минут фоновой обработки и нескольких минут ручного просмотра красных ячеек.

Практическая значимость работы определяется тремя факторами. Плагин готов к установке в любой инстанс Moodle версии 4.0 LTS и выше, развёртывание занимает пять минут и не требует модификаций ядра платформы. Решение импортонезависимо: данные не покидают контур университета, что устраняет вопросы соответствия ФЗ-152 и соответствует курсу на импортозамещение. Исходный код плагина и схема базы данных вынесены в приложение Г и доступны для воспроизведения и доработки силами ИТ-служб других вузов.

На наш взгляд, работа открывает пять направлений дальнейшего развития. Первое — переход от лексических алгоритмов к семантическим эмбеддингам типа SBERT [37], [38], [39] для детекции перефразирования, которое шинглы пропускают по построению. Второе — поддержка OCR для распознавания рукописных решений в изображениях (актуально для математических и физических дисциплин). Третье — опциональная кросс-проверка с внешним сервисом «Антиплагиат» [3] для выпускных работ, где требуется сравнение с веб-базой. Четвёртое — агрегированная админская панель с метриками по курсам и факультетам. Пятое — адаптация под Moodle Workplace для корпоративного обучения сотрудников [15].
