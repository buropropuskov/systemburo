# ВВЕДЕНИЕ

Воскресенье, девять вечера. В почте висит двадцать восемь файлов DOCX, плюс архив с решениями на Python, плюс четыре отчёта в PDF, которые староста прислала «чтобы всё вместе». До понедельника нужно выставить оценки. Преподаватель открывает первую пару работ, перелистывает, сравнивает глазами формулировки, ищет совпадения. На одну пару уходит полторы минуты. В группе из 25 студентов таких пар получается 300, в группе из 30 — уже 435. Семь с половиной часов непрерывной проверки только на одну группу, и это при условии, что преподаватель не отвлекается и не теряет концентрацию. Moodle, на котором держится значительная часть российской и мировой дистанционки (свыше 200 000 площадок в 240 странах [1]), штатного инструмента попарного сравнения работ внутри задания не предлагает. Стандартный элемент «Задание» умеет принимать файл, но дальше преподаватель остаётся один на один с папкой загрузок.

Существующие сервисы проблему закрывают лишь частично. Turnitin ищет совпадения с внешней веб-базой и подписными хранилищами, попарное сравнение внутри группы у него вторично, а стоимость от трёх долларов за студента в год делает его малодоступным для бюджетного вуза [2]. «Антиплагиат» закрывает русскоязычный сегмент и интегрируется с Moodle через отдельный коммерческий плагин, но форматы исходного кода поддерживает формально, без учёта синтаксиса языка [3]. MOSS, разработанный в Стэнфорде, бесплатен и силён по коду, однако это внешний CLI-сервис без штатной интеграции с LMS и без работы с DOCX, PDF или таблицами [4]. JPlag — проект с открытым кодом, ориентированный строго на исходники программ; по опыту автора, для смешанных заданий «текст плюс код плюс таблица» он не подходит [5]. Единого инструмента, который решал бы задачу целиком и жил внутри Moodle, на рынке попросту нет.

Цель работы: повышение эффективности процесса оценивания степени самостоятельности решения задач студентами за счёт снижения трудозатрат преподавателя на проверку заданий текущего контроля.

Для достижения цели поставлены четыре задачи:

1. Провести анализ существующих инструментов проверки уникальности работ, выявить их недостатки при применении в LMS, сформулировать требования к разрабатываемой системе.
2. Провести моделирование предметной области системы оценивания студентов.
3. Спроектировать модуль проверки работ на заимствования и интегрировать его в систему Moodle.
4. Реализовать и провести тестирование разработанного плагина, оценить эффективность снижения трудозатрат преподавателя при проверке работ.

Объектом исследования выступает процесс оценивания степени самостоятельности решения задач студентами в системе дистанционного обучения Moodle. Предмет — плагин попарного сравнения студенческих работ в рамках одного задания Moodle, реализующий автоматический анализ заимствований для текстовых документов и исходного кода.

Работа разбита на четыре главы, каждая вытекает из предыдущей. Первая анализирует Turnitin, «Антиплагиат», MOSS и JPlag, фиксирует их ограничения применительно к LMS и на этом основании формулирует функциональные и нефункциональные требования [6], [7]. Вторая выстраивает модель предметной области: акторов, диаграммы вариантов использования и бизнес-процессы «как есть» и «как будет» в нотациях UML и BPMN. Третья превращает требования в проект: архитектуру плагина типа `plagiarism`, схему базы данных, алгоритмы шинглов с коэффициентом Жаккара для текста [8] и Winnowing для кода [9], интеграцию через Moodle Plugin API [10]. Четвёртая описывает реализацию на PHP 8.1, тестирование PHPUnit и количественную оценку снижения трудозатрат: семь с половиной часов ручной проверки против пятнадцати минут фонового выполнения на сервере.
