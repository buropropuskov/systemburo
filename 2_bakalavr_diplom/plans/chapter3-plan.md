## 3.1 Этапы разработки и обоснование решений (3-4 стр.)

### Реализация серверной части (Go)
- Структура проекта (Clean Architecture): cmd/, internal/ (handler, service, repository, model, middleware, config), pkg/
- Листинг 3.1: структура проекта (tree, 10-15 строк)
- Конфигурация: .env, Echo router, GORM, graceful shutdown
- Листинг 3.2: main.go (15-20 строк)
- Модели данных: Go-структуры с JSON-тегами
- Листинг 3.3: модель Equipment (10 строк)
- Repository: CRUD для оборудования, обработка ошибок с fmt.Errorf
- Листинг 3.4: метод CreateRepairRequest (10-15 строк)
- Middleware: JWT-аутентификация, RBAC, CORS, логирование

### Реализация клиентской части (Vue 3)
- Структура: feature-based организация, Vite
- Pinia для state management, Vue Router с navigation guards
- Листинг 3.5: компонент дашборда (15-20 строк, script setup)
- Axios interceptors для JWT

- Только ключевые фрагменты, полный код в приложения
- Все листинги в рамке, белый фон

### Сценарии использования (описать текстом):
1. **Создание заявки на ремонт**: оператор -> форма -> выбор оборудования -> описание неисправности -> отправка -> уведомление инженера
2. **Обработка заявки**: инженер -> оценка приоритета -> назначение техника -> техник выполняет -> отметка завершения
3. **Плановое ТО**: инженер задаёт график -> система формирует задания по дате -> техник выполняет
