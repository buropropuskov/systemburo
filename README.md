# Rentu: разбор интерфейса и цен

Rentu (rentu.ru) - SaaS-платформа для управляющих компаний торговых центров. Компания из Тюмени и Москвы, работает с 2019 года, в реестре российского ПО запись №31370. По их данным: 170+ ТЦ, 14 000+ арендаторов.

Состав продукта:

- **Платформа арендодателя** (malls.rentu.ru): товарооборот арендаторов через ОФД, антифрод, чек-ап арендаторов, аренда с оборота.
- **Трафик**: посещаемость со счётчиков и видеоаналитики на IP-камерах, тепловые карты, конверсия в выручку.
- **Портал арендатора** (portal.rentu.ru): заявки, пропуска, кассы, сдача отчётов ТО, страховки, документы, рассылки. Есть мобильная версия (sd.rentu.ru) с QR-сканером.
- **Rentu AI**: вопросы к данным ТЦ на естественном языке.
- **External API v2**: REST, envelope `{success, data, meta, error}`, тарифы Basic/PRO.

Все скриншоты в `screens/` вырезаны из публичных презентаций вебинаров Rentu 2025-2026 годов. Это экраны живой системы на демо-данных (ТЦ "СуперМОЛЛ"), а не рисунки с лендинга.

## Что видно про пропуска

В первом разборе я написал, что пропуска у Rentu - "обычный тикет". Экраны это опровергают: там отдельная сущность с собственной формой.

- **Пропуск** - отдельная сущность, связанная с заявкой (`ticket_uid`). Тип: человек или транспорт.
- Форма на человека: фото, ФИО, вид и номер документа, флаги "является сотрудником" и "постоянный пропуск", должность, период действия (дневной / ночной / днём и ночью), даты, часы, комментарий, файлы, согласие с гарантийным заявлением.
- На транспорт: госномер, марка, тип ТС (например `truck_1_5_3t`), метки вроде "Разгрузка".
- Статусы пропуска: на согласовании, согласован, отозван заявителем, отозван объектом, отклонён.
- Статусы заявки: новая, в работе, согласована, согласована с условиями, отозвана, отклонена. Условия согласования пишет каждый отдел отдельно.
- Маршрутизация: отделы ТЦ (маркетинг, аренда, охрана, администрация, эксплуатация) и матрица прав сотрудника по отделам.
- Мобильная версия: список заявок, согласование отделом в один тап, **сканер QR** (проверка пропуска охраной).
- Типы заявок иерархические: "Ввоз / вывоз" с вложенным "Ввоз оборудования", у них параметры (например вход №3) и дополнительные поля формы.
- Заявки и пропуска отдаются во внешнем API на любом тарифе: `GET /api/external/v2/sc/{sc_id}/portal/passes` и `.../portal/tickets`.
- В презентации заявлено: "RENTU является оператором персональных данных и соответствует 152-ФЗ". Данные хранятся у Rentu, это облако.

## Отличия от systemburo

| | Rentu | systemburo |
|---|---|---|
| Кто владелец данных | Rentu как оператор ПД, облако | заказчик, установка на свой сервер |
| Для кого | ТЦ и арендаторы | бюро пропусков объекта, охрана, согласующие и принимающие |
| Пропуск | часть портала арендатора, привязан к заявке и торговой точке | ядро системы |
| Охрана | QR-сканер в мобильной версии | роль охраны, отметки прохода и их отмена, журнал проходов |
| Согласование | отделы ТЦ, "с условиями" | согласующие, принимающие, видимость по таблицам постов |
| Деньги | товарооборот, ОФД, аренда с оборота, страховки | нет |
| Проверка людей | не видно | чёрные списки, сквозной поиск, нормализация |
| ПД | заявлено соответствие 152-ФЗ | согласие субъекта, сроки хранения, обезличивание, журнал уничтожения, шифрование |
| Цена пропускного модуля | 0 / 9 900 / 19 900 ₽ в месяц за портал целиком | поставка на сервер заказчика |

Вывод: для ТЦ, которые уже сидят на Rentu ради товарооборота, пропуска достаются бесплатно внутри портала, и там это закрытый конкурент. На объектах без торговли и аренды с оборота (бизнес-центры, производство, режимные объекты), где нужен on-prem и журнал проходов, Rentu не играет.
