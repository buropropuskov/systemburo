# Системный анализ: комплект конспектов

Учебные материалы по профессии системного аналитика. Ветка независимая: своя история,
никакого кода, к разработке основного продукта отношения не имеет.

## Состав

| Файл | О чём | Объём |
|---|---|---|
| `pdf/01-roadmap.pdf` | Профессия, границы роли, карта компетенций, план обучения по этапам, портфолио, грейды | 15 с. |
| `pdf/02-requirements.pdf` | Виды требований, выявление, критерии качества, приоритизация, SRS и ГОСТ, user story, use case, трассируемость | 16 с. |
| `pdf/03-notations.pdf` | BPMN, UML (5 диаграмм), ERD, C4, текстовые нотации, чек-лист качества диаграммы | 14 с. |
| `pdf/04-api-integrations.pdf` | HTTP и REST, OpenAPI, SOAP, gRPC, GraphQL, брокеры, идемпотентность, устойчивость, шаблон постановки | 22 с. |
| `pdf/05-databases.pdf` | Модель данных, нормализация, SQL, транзакции и изоляция, индексы, масштабирование, NoSQL | 17 с. |
| `pdf/06-interview.pdf` | Этапы отбора, банк вопросов с разбором, практические задания, поведенческие вопросы, переговоры, как пережить | 19 с. |

Исходники в `src/docs/*.md`, оттуда и правятся: PDF пересобирается, руками его не трогают.

## Пересборка

```
node src/build.mjs        # все документы
node src/build.mjs 04     # только тот, чей файл начинается с 04
```

Зависимости (`markdown-it`, `playwright`) в ветке не хранятся: скрипт берёт их из соседнего
чекаута либо из каталога, указанного переменной окружения.

```
ANALYST_NODE_MODULES=/путь/к/node_modules node src/build.mjs
```

Печать идёт через Chromium из Playwright, поэтому нужен установленный браузер
(`npx playwright install chromium`).

## Как добавить документ

1. Положить `src/docs/NN-имя.md`. Заголовки уровня `##` становятся разделами и начинаются
   с новой страницы, `###` вкладываются в них. Нумерация разделов и оглавление строятся сами.
2. Добавить запись в `src/docs/meta.json`: подпись над заголовком, название, аннотация.
3. Собрать и закоммитить `.md` вместе с `.pdf`.
