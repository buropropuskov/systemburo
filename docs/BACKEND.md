# Backend — архитектура и контракты

Сверено с кодом 14.10.2026. Требование Go в `go.mod` — 1.26.9; сборочные стадии `Dockerfile` используют Go 1.27.2. PostgreSQL — 16, HTTP — Echo v4, доступ к БД — GORM/pgx. Точные зависимости и контрольные суммы находятся в `go.mod`/`go.sum`.

## Запуск и остановка

Источник порядка — `cmd/server/main.go`: конфигурация и её валидация → журналирование → ключ шифрования → подключение к БД → миграции/дошифровка → начальные данные → сервисы и обработчики → маршруты → фоновые задачи → HTTP-сервер. `SWAGGER_ENABLED`, а не уровень журналирования, управляет Swagger UI.

Миграции выполняются при старте; они меняют схему и могут преобразовывать данные. Перед обновлением нужна проверяемая резервная копия. Возврат старого образа сам по себе не возвращает прежнюю схему. Точное содержимое — `internal/database/migrate.go`, список моделей — `AllModels()`; число моделей не равно числу таблиц с динамическими партициями работающей БД.

Остановка обрабатывает сигнал, завершает HTTP и обслуживаемые очереди с ограниченным временем ожидания. Фоновые задачи получают контекст остановки. Их интервалы и настройку хранения см. в руководстве сопровождения; не запускать дополнительные планировщики для уже встроенных задач.

## Структура

| Каталог | Ответственность |
|---|---|
| `cmd/server` | Запуск, CLI обслуживания и планировщики |
| `internal/router` | Фактические маршруты и middleware каждого пути |
| `internal/handlers` | HTTP-вход, DTO, валидация, ответы |
| `internal/services` | Бизнес-правила, доступ к объектам, транзакции |
| `internal/models`, `internal/database` | Модели, схема, начальные данные, хранение |
| `internal/middleware` | JWT, права, блокировки, аудит, ограничения запросов |
| `internal/crypto`, `internal/imaging`, `internal/upload` | Шифрование, обработка изображений, загрузки |

## Защищённый запрос

Глобально подключены RequestID, Logger/Recover, защитные заголовки, CORS, ограничение запросов, аудит ПД и журнал запросов. Для группы `/api` защищённая цепочка начинается с JWT и включает проверку техработ, блокировки, согласия на обработку ПД, обязательной смены пароля, активности и ограничений входа под другим пользователем. У конкретного маршрута могут быть дополнительные права; регистрация в `router.go` важнее схематичного перечня.

JWT middleware декодирует access-токен. Решение о разрешении операции принимается действующим резолвером прав и проверками видимости объекта; `type_id == 6` не является современной проверкой администратора. См. [модель прав](access-control/README.md).

## Маршруты и сессия

Базовый путь API — `/api`. `/health` находится вне него. В публичной части зарегистрированы вход, продление сессии, типы пользователей и общедоступные настройки. Публичной регистрации `/register` в текущем роутере нет. События и скачивание архива используют отдельные билеты: отсутствие JWT на маршруте не означает свободный доступ к данным.

Access-токен по умолчанию живёт 15 минут (`JWT_ACCESS_TTL`), refresh — 168 часов (`JWT_REFRESH_TTL`). Refresh хранится в HttpOnly cookie с `Path=/api`, `SameSite=Strict` и управляемым `Secure`; в БД хранится хеш. Ответ входа/продления не отдаёт refresh в JSON. При продлении выполняется ротация. Загрузка `/api/uploads` защищена FileAccess; просмотр сканов дополнительно ограничен принадлежностью. Нельзя подменять эту модель прежним описанием публичной статики.

Swagger — вспомогательное описание. Фактический контракт сверять по маршруту, DTO, handler и клиенту. В частности, старые аннотации входа всё ещё описывают возврат пары токенов, хотя handler исключает refresh из JSON. Изменение этих Go-аннотаций и регенерация Swagger выделяются отдельно от правки текста.

## Вход и ответы

`BindAndValidate` выполняет bind и структурную валидацию DTO; доменные зависимости проверяются сервисом. Не добавлять `required` старому полю без проверки реального вызова frontend. Query, опциональное тело и частичное обновление требуют собственного явного контракта.

Обычный JSON использует `{success, data, meta, error}`; отдельные ответы об отказе содержат дополнительные маркеры. `apiRequest` на frontend возвращает Response с переопределённым `.json()`, а не готовый объект. Для пагинации использовать сырой envelope. Вложенность `data.table` и аналогичных ответов нужно проверять, не угадывать по URL. Потоки файлов не обязаны иметь JSON envelope.

Частичный `PUT` человека: отсутствие опционального поля означает «не менять», а не пустое значение. При возражении проверять фактическое изменение защищаемых ПД: непереданные ФИО/должность не вызывают `409`, реальное запрещённое изменение сохраняет конфликт. Реализация и регрессионные случаи — `internal/services/employee_service.go` и соответствующие тесты.

## Сроки, пересылка и отметки

`entity_period.go` задаёт единое вычисление срока: наследуемый срок вложения либо целиком индивидуальный срок записи. Нельзя смешивать отдельные пустые поля двух режимов. Ручная запись без дат может быть бессрочной. Срок сам по себе не разрешает доступ: нужны видимость, активность и подходящий статус заявки.

Общий срок меняется в непрочитанной заявке, обработке и в работе; индивидуальный — в работе либо у действующей ручной записи. Операции имеют разные права. Изменение срока не сбрасывает уже поданные голоса. Привязка из карточки переносит выбранную запись, не соседей ручного вложения.

Пересылка хранит назначение получателей и состав материалов. Отозванная заявка пересылается для просмотра. При чтении новой истории видимость получателей проверяется по ID; у старой записи без ID непроверенные имена не восстанавливаются по совпадению текста.

Просроченный допуск и нахождение на территории — разные состояния. Незакрытый вход удерживает строку для выхода, но не разрешает новый вход. Исправление учёта и отмена исправления имеют отдельные проверки, причину и аудит. Подробные пользовательские шаги — в руководствах ролей.

## Проверки и эксплуатация

`make lint` выполняет `go vet ./...`, `make test` — `go test ./... -v -count=1` в контейнере `go-backend`. Команды запускают проверки, не подменяют результат конкретного прогона. Интеграционным тестам нужна изолированная БД; общий CleanDB нельзя параллелить между независимыми исполнителями.

Настройки и их реальные умолчания — `internal/config/config.go`. `.env.example` — стартовый пример, не исчерпывающая спецификация. Шифрование обязательно по умолчанию (`REQUIRE_ENCRYPTION=true`). Подробности защиты — [SECURITY.md](SECURITY.md), поставки — [DEPLOYMENT.md](DEPLOYMENT.md).
