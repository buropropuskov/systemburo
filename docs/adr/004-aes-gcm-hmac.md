# ADR-004: AES-256-GCM + HMAC-SHA256 для шифрования ПД

**Статус:** Принято (регуляторное требование — 152-ФЗ)

## Контекст

Закон 152-ФЗ требует защиты персональных данных at rest. Паспортные данные сотрудников хранятся в PostgreSQL. Нужно шифрование, которое:
- Не ломает существующие запросы (WHERE по номеру паспорта)
- Прозрачно для бизнес-логики
- Отключаемо для dev-окружения

## Решение

- **AES-256-GCM** для шифрования (аутентифицированное, NIST-approved)
- **HMAC-SHA256** для детерминированного поиска (отдельные `*_hmac` колонки с индексами)
- **GORM hooks** (BeforeSave/AfterFind) для прозрачности
- **Passthrough** при пустом ключе

## Последствия

**Плюсы:**
- AES-GCM: каждое шифрование уникально (random nonce), защита от подмены
- HMAC: поиск `WHERE passport_hmac = ComputeHMAC(value)` без расшифровки всей таблицы
- GORM hooks: сервисы не знают о шифровании — нулевые изменения в бизнес-логике
- Passthrough: dev работает без ключа, prod — с ключом

**Минусы:**
- HMAC позволяет определить совпадение значений (если два сотрудника имеют одинаковый паспорт — одинаковый HMAC). Для паспортов это допустимо (уникальны)
- Нет ротации ключей — смена ключа требует перешифровки всех данных
- Шифрованные данные увеличивают размер колонки (base64 overhead ~33%)
