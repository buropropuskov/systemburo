## 1. Архитектура фронтенда

### Технологический стек

| Технология | Версия / Описание |
|---|---|
| **Фреймворк** | Vue 3.2.13 (Options API) |
| **Роутинг** | Vue Router 4.4.5 |
| **Сборка** | Vue CLI 5 (`@vue/cli-service`) |
| **Стилизация** | Scoped CSS, SCSS, шрифт Montserrat |
| **HTTP-клиент** | Fetch API (нативный, без Axios) |
| **Экспорт данных** | `exceljs`, `xlsx` (экспорт в Excel) |
| **UI-библиотеки** | `vue-select` (кастомные селекты) |

### Иерархия компонентов

```
App.vue (корень: авторизация, сессия, модалы)
├── TheHeader.vue (шапка с информацией о пользователе)
├── NavMenu.vue (боковое меню навигации)
├── SessionExpiredModal.vue (модал истечения сессии)
├── FeedbackModal.vue (модал обратной связи)
└── <router-view> (страницы)
    ├── LoginComponent.vue
    ├── CreateApplication.vue (сложная форма заявки)
    ├── TablesComponent.vue (динамические таблицы)
    ├── ApplicationsCenter.vue (центр согласования)
    ├── AccountComponent.vue (личный кабинет + админ-панели)
    ├── CarsView.vue
    ├── EmployeeView.vue
    ├── NewsAndReview.vue
    └── FeedbackPage.vue
```

**App.vue** выступает корневым компонентом и выполняет следующие функции:

- Хранит состояние авторизации (`isAuthenticated`)
- Определяет роль пользователя (`isBuropropuskov`)
- Управляет проверкой срока действия токена (polling каждые 10 секунд)
- Отображает глобальные модальные окна (сессия, обратная связь)
- Оборачивает страницы через `<router-view>`

## 2. Маршрутизация

### Таблица маршрутов

| Путь | Компонент | Требуется авторизация | Только для бюро |
|---|---|---|---|
| `/` | `LoginComponent` | Нет | Нет |
| `/submit-form` | `CreateApplication` | Да | Нет |
| `/table` | `TablesComponent` | Да | Да |
| `/table/:tableName` | `TablesComponent` | Да | Да |
| `/personal-cabinet` | `AccountComponent` | Да | Нет |
| `/carsview` | `CarsView` | Да | Нет |
| `/center` | `ApplicationsCenter` | Да | Нет |
| `/table-constructor` | `TableConstructor` | Да | Да |
| `/number-format` | `NumberFormat` | Да | Да |
| `/employeesview` | `EmployeeView` | Да | Нет |
| `/news` | `NewsAndReview` | Да | Нет |
| `/admin/feedback` | `FeedbackPage` | Да | Да |

### Навигационные гарды

Глобальный guard `beforeEach` выполняет следующие проверки:

1. **Валидация JWT** -- проверяет, не истек ли access token. Если токен просрочен, пользователь перенаправляется на страницу входа (`/`).
2. **Проверка авторизации** -- неавторизованные пользователи не могут перейти на защищенные маршруты.
3. **Проверка роли** -- маршруты с пометкой "Только для бюро" (например, `/table`, `/table-constructor`, `/number-format`, `/admin/feedback`) доступны только пользователям с ролью `isBuropropuskov` (`type_id === 6`). Остальные пользователи перенаправляются на доступную страницу.

### Параметры маршрутов

- `/table/:tableName` -- динамический параметр `tableName` определяет, какая таблица отображается в компоненте `TablesComponent`. Компонент реагирует на изменение параметра через `watch`.

## 4. Управление состоянием

### Отсутствие централизованного хранилища

В проекте **не используется** Vuex или Pinia. Все состояние управляется локально.

### Принципы управления данными

| Механизм | Описание |
|---|---|
| **Локальное состояние** | Каждый компонент хранит свое состояние в `data()`. Данные запрашиваются при монтировании (`mounted()` / `created()`). |
| **Props (сверху вниз)** | Родительские компоненты передают данные дочерним через props. |
| **Events (снизу вверх)** | Дочерние компоненты уведомляют родителей через `$emit`. |
| **localStorage** | Хранение токенов: `token` (access), `refreshToken` (refresh). |
| **Глобальное состояние** | `isAuthenticated` и данные пользователя хранятся в `App.vue` и передаются через props. |

### Определение роли пользователя

```javascript
// В App.vue
computed: {
  isBuropropuskov() {
    return this.user && this.user.type_id === 6;
  }
}
```

Роль `isBuropropuskov` (type_id === 6) определяет принадлежность пользователя к бюро пропусков и открывает доступ к административным функциям.

### Поток данных

```
App.vue (isAuthenticated, user, isBuropropuskov)
  │
  ├── props ──> TheHeader.vue (user)
  ├── props ──> NavMenu.vue (isBuropropuskov)
  └── props ──> <router-view> (user, isBuropropuskov)
                    │
                    ├── $emit ──> App.vue (logout, session-refresh)
                    └── fetch() ──> Backend API
```

## 5. Сессия и токены

### Параметры токенов

| Параметр | Значение |
|---|---|
| **Access token** | JWT, время жизни 120 минут (2 часа) |
| **Refresh token** | Время жизни 24 часа |
| **Хранение** | `localStorage` (ключи: `token`, `refreshToken`) |

### Жизненный цикл сессии

1. **Авторизация** -- пользователь вводит логин/пароль, сервер возвращает пару токенов (access + refresh). Токены сохраняются в `localStorage`.

2. **Проверка токена** -- в `App.vue` запущен интервал проверки каждые **10 секунд**. Из JWT декодируется поле `exp` и сравнивается с текущим временем.

3. **Предупреждение** -- за **300 секунд (5 минут)** до истечения access token отображается модальное окно `SessionExpiredModal.vue` с предложением продлить сессию.

4. **Продление сессии** -- при нажатии "Продлить" отправляется запрос:
   ```
   POST /refresh-token
   Body: { refreshToken: "..." }
   ```
   Сервер возвращает новую пару токенов.

5. **Автовыход** -- если пользователь не продлил сессию и access token истек, происходит автоматический выход: токены удаляются из `localStorage`, пользователь перенаправляется на страницу входа.

### Схема проверки токена

```
setInterval (каждые 10 сек)
  │
  ├── Декодировать JWT → получить exp
  ├── Вычислить оставшееся время: exp - now
  │
  ├── Если оставшееся время <= 0:
  │     └── Автовыход (очистка токенов, редирект на /)
  │
  ├── Если оставшееся время <= 300 сек:
  │     └── Показать SessionExpiredModal
  │
  └── Иначе:
        └── Ничего не делать
```

## 6. Стилизация

| **Хардкод URL** | 48 файлов содержат жестко прописанный адрес `http://localhost:8080`. При деплое на сервер приложение не будет работать без ручной замены. | Вынести базовый URL в переменную окружения (`VUE_APP_API_URL`) или в конфигурационный файл. Использовать `process.env.VUE_APP_API_URL` во всех запросах. |
| **Отсутствие state management** | Нет Vuex/Pinia. Все состояние локальное. При росте приложения это приводит к дублированию запросов, prop drilling, рассинхронизации данных. | Внедрить Pinia для хранения: данных пользователя, списков справочников, состояния заявок. |
| **Отсутствие TypeScript** | Весь код на JavaScript без типизации. Нет проверки типов при компиляции, сложнее рефакторить, больше рантайм-ошибок. | Постепенная миграция на TypeScript. Начать с новых компонентов и общих утилит. |

### Проблемы производительности

| Проблема | Описание | Рекомендация |
|---|---|---|
| **Нет lazy loading маршрутов** | Все компоненты страниц импортируются статически и загружаются при старте приложения, увеличивая размер бандла. | Использовать динамические импорты: `component: () => import('./views/TablesComponent.vue')`. |
| **Token polling** | Проверка токена запускается через `setInterval` каждые 10 секунд. Это избыточная нагрузка (лишние вычисления). | Заменить на `setTimeout` с расчетом оставшегося времени до истечения токена. Пересчитывать таймер только после обновления токена. |

### Архитектурные рекомендации

| Проблема | Описание | Рекомендация |
|---|---|---|
| **Vue CLI 5 deprecated** | Vue CLI официально не поддерживается. Обновления безопасности и новые функции не выходят. | Мигрировать на **Vite** -- значительно быстрее dev-сервер (HMR за миллисекунды), меньше конфигурации, активная поддержка сообществом. |
| **Отсутствие тестов** | В проекте нет ни unit-тестов, ни e2e-тестов. Любые изменения могут сломать существующий функционал без обнаружения. | Внедрить Vitest (unit) + Playwright или Cypress (e2e). Начать с тестирования критических сценариев: авторизация, создание заявки, согласование. |
| **Нет HTTP-обертки** | Fetch API вызывается напрямую в каждом компоненте. Повторяется логика добавления заголовков, обработки ошибок, refresh токена. | Создать сервисный слой (`api.js`) с единой функцией запросов, автоматическим добавлением `Authorization` заголовка и обработкой 401 ответов. |
| **Нет обработки ошибок** | Ошибки API-запросов обрабатываются несистемно -- где-то через `alert()`, где-то игнорируются, где-то через `console.error()`. | Реализовать единую систему уведомлений об ошибках (toast-нотификации) и глобальный обработчик ошибок Vue (`app.config.errorHandler`). |

### Приоритет исправлений

1. **Высокий**: Вынести `localhost:8080` в переменные окружения (блокирует деплой)
2. **Высокий**: Создать HTTP-обертку (уменьшит дублирование кода на 30-40%)
3. **Средний**: Добавить lazy loading маршрутов (улучшит время начальной загрузки)
4. **Средний**: Внедрить Pinia (упростит управление состоянием)
5. **Низкий**: Миграция на Vite (улучшит DX, не влияет на продакшен)
6. **Низкий**: Миграция на TypeScript (долгосрочное улучшение)
