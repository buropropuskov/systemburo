# TgBridge

Мост между игровым чатом Minecraft и топиком Telegram. Написан под Paper 26.3
после того, как готовый MultiMessageBridge начал вешать сервер: он ходил в сеть
из главного потока, и при обрывах связи до api.telegram.org старт растягивался
на три минуты, а чат замолкал до перезапуска.

## Что делает

- чат из игры в топик и обратно, ссылки в игре кликабельные;
- вход, выход, смерти, старт, остановка и перезагрузка сервера;
- отказы во входе: сканеры и попытки зайти чужим ником;
- предупреждения о низком TPS и нехватке места на диске;
- команды из Telegram: `/online`, `/tps`, `/status`, `/map`;
- в консоли: `/tgbridge status`, `/tgbridge reload`, `/tgbridge test`;
- переписку и служебные сообщения можно развести по разным топикам;
- понятные имена вместо юзернеймов через словарь в конфиге.

## Чем отличается от готовых мостов

- Ни одной сетевой операции в главном потоке: отправка и приём живут в своих потоках.
- Лимит Telegram (около 20 сообщений в минуту на группу) обрабатывается по `retry_after`,
  а не вслепую повторами.
- Соседние события склеиваются в одно сообщение: перезапуск сервера больше не даёт
  пачку из шести уведомлений подряд.
- Недоставленное переживает перезапуск сервера: очередь сохраняется на диск.
- Длинные сообщения обрезаются до лимита Bot API, а не теряются с ошибкой.
- Очередь с повторами (2, 5, 10, 30, 60 секунд) и отбрасыванием сообщений старше
  десяти минут, чтобы после долгого обрыва не сыпалась стена устаревшей переписки.
- Приём переподключается сам после любой сетевой ошибки.
- На прощальное сообщение при выключении даётся ровно две секунды.
- `apiBase` в конфиге: если Telegram недоступен напрямую, адрес меняется на свой
  релей без правок кода.

## Сборка

JDK 25 обязателен: Paper 26.3 собран под него.

```
docker run --rm -u "$(id -u):$(id -g)" -v "$PWD":/w -w /w \
  -e GRADLE_USER_HOME=/w/.gradle-home gradle:9-jdk25 gradle jar --no-daemon
```

Готовый файл появится в `build/libs/`.

## Установка

1. Положить jar в `plugins/`, запустить сервер, остановить.
2. В `plugins/TgBridge/config.yml` заполнить `token`, `chatId`, `threadId`.
3. `tgbridge reload` в консоли, проверить `tgbridge status`.

Узнать `chatId` и `threadId` можно из ссылки на сообщение в топике вида
`t.me/c/4455608654/27/31`: первое число с префиксом `-100` даёт chatId,
второе - номер топика.
