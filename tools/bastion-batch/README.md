# Пакетное создание заявок в Бастион-2

Утилита для АРМ «Бюро пропусков» (Бастион-2, проверено на 2.1.14). Заводит десятки
однотипных заявок за один заход вместо ручного ввода каждой: фамилия, фотография,
организация, подразделение, должность и уровень доступа берутся из уже созданной
заявки, а меняются только имя, табельный номер и корпоративный код персоны.

Типовой случай — пачка карт на организацию, где записи различаются лишь номером:
«ИП Зайцева № 1» … «ИП Зайцева № 100».

## Как это работает

Бастион умеет выгружать пропуска в CSV и принимать такой же файл обратно через
мастер импорта. Утилита встаёт между этими двумя операциями:

1. В Бюро пропусков заводится **одна** заявка со всеми нужными реквизитами.
2. Она выгружается: Инструменты → Сервис → «Экспорт пропусков» → CSV.
3. Утилита размножает эту строку до нужного количества.
4. Результат загружается обратно: Инструменты → Сервис → «Импорт пропусков».

Номера карт в файл не пишутся: карта присваивается при выдаче пропуска, и настольный
считыватель заносит её в справочник сам. Так работает и с непоследовательными
номерами карт, которые диапазоном в справочник не добавить.

## Два варианта

| Файл | Для чего |
|---|---|
| `bastion_zayavki.py` | Оконное приложение: выбор файла, поля ввода, сводка по выгрузке, журнал |
| `batch.py` | То же без интерфейса, настройки в начале файла. Когда нужно быстро и без сборки |
| `sborka.bat` | Собирает `bastion_zayavki.py` в один `.exe` через PyInstaller |

Обе версии используют только стандартную библиотеку Python 3.8+. Собранный exe
весит около 10 МБ и работает на машине без установленного Python.

## Особенности формата выгрузки

Это не догадки, а то, обо что утилита спотыкалась на реальных файлах.

**Две строки заголовка.** Экспорт пишет сначала технические имена полей
(`NAME;FIRSTNAME;SECONDNAME;…`), затем русские подписи к ним
(`Фамилия;Имя;Отчество;…`), и только с третьей строки идут данные. Если принять
вторую строку за данные, в базу уедут записи с фамилией «Фамилия» и должностью
«Должность», причём словарные поля создадут одноимённый мусор в справочниках.

**Корпоративный код персоны собирается из Ф.И.О.** и выглядит как
`ИП Зайцева № 1  ` с хвостовыми пробелами. Мастер импорта сопоставляет строки с
базой в первую очередь по нему: одинаковый код на всех строках означает, что одна
персона будет обновлена N раз вместо создания N новых. Утилита подставляет код по
образцу, заменяя в нём номер.

**Корпоративный код пропуска (`PASSCC`) очищается** — он у каждого пропуска свой,
дублировать нельзя.

**Фотография лежит вне CSV.** В колонке `PHOTO` только имя файла, сама картинка —
в подкаталоге `<имя_файла>.CSV_PHOTO` рядом. Импорт ищет её в подкаталоге, названном
по имени импортируемого файла, поэтому утилита копирует папку под новое имя. Все
строки ссылаются на одну и ту же картинку, размер файла от количества записей не
растёт.

**Кодировка cp1251, разделитель `;`.** Определяются автоматически и сохраняются в
результате. Открывать выгрузку в Excel и сохранять из него нельзя: он съедает
ведущие нули в табельных номерах и меняет кодировку.

**Ограничения полей Бастиона:** фамилия, имя и отчество — не более 20 символов
каждое; табельный номер — 20 символов, набор допустимых символов задаётся в общих
настройках Бюро пропусков.

## Нумерация

По умолчанию утилита читает выгрузку, находит максимальный номер в именах и
максимальный табельный, и продолжает со следующих. Достаточно выгрузить последнюю
созданную заявку — вся история не нужна.

Ручной режим пригодится, когда табельные шли с пропусками или когда автогенерация
табельных номеров в Бастионе выдала значение из чужого диапазона.

## Проверка перед боевым прогоном

Сначала три записи, не сто. Импортировать, открыть свойства любой созданной заявки
и убедиться, что на месте фотография, отчество и организация, а табельные не
пересеклись с существующими сотрудниками. Что не прошло, мастер импорта покажет в
таблице «Неимпортированные пропуска» и выгрузит в Excel.

Файлы выгрузок содержат персональные данные и в репозиторий не коммитятся.
