# Сборка и сверка документации

Источник текста — Markdown в каталоге каждого документа. Сборщик создаёт рядом DOCX и PDF. Инструменты восстановлены из `docs/tech-docs`; актуальные исходники, рисунки и собранные экземпляры ведутся вместе с документацией в основной истории проекта. Загрузка готовых руководств в приложение выполняется отдельным шагом.

## Среда

- Python 3.10 или новее и `python-docx` (проверено с 1.2.0).
- LibreOffice с командой `soffice`, Poppler с `pdftotext` и `pdfinfo`.
- Git и актуальная ссылка `origin/dev` для проверки кода и долга.

Команды ниже выполняются из корня репозитория. Используйте выбранный Python одной среды. На Windows выполняется тот же Python-код без Bash, grep, sed и awk.

```sh
python -m pip install -r Документация/src/requirements.txt
python Документация/src/build_docs.py --check-env pilot
python Документация/src/doc_facts.py
python Документация/src/docs_impact.py BASE..HEAD
python Документация/src/build_docs.py pilot
```

`--check-env` проверяет инструменты, исходники и рисунки без изменения документов. Если исполняемые файлы не находятся через PATH, задайте их абсолютные пути в `DOC_SOFFICE`, `DOC_PDFTOTEXT`, `DOC_PDFINFO`. Отдельный каталог источников задаётся `DOCS_SOURCE_DIR`: проверяется текущий код репозитория, а читаются документы из указанного каталога. При сборке выходные DOCX/PDF также записываются туда; для диагностики используйте отдельную копию.

Доступные ключи документов: `overview`, `deploy`, `pilot`, `user`, `guard`, `user_howto`, `guard_howto`, `approver`, `acceptor`, `admin`. Без ключа собирается весь комплект. Для обычной правки выбирайте затронутые документы, запускайте одну сборку за раз.

## Как читать результаты

`doc_facts.py` сверяет числовые якоря, реестры, параметры окружения, команды, файлы и ссылки. Код 1 означает незакрытое расхождение или недостоверную проверку; ошибка Git или чтения не считается отсутствием изменений. Число тестов — число найденных объявлений по поддерживаемым шаблонам, а не число исполненных тестовых случаев. Число таблиц — базовые модели и статические SQL-таблицы, без динамических партиций и оставшихся после старых выпусков таблиц конкретной БД.

`docs_impact.py` указывает разделы, которые нужно сверить вручную. Его код 0 означает успешный анализ, а не закрытие долга. Файлы вне карты требуют рассмотрения. Без диапазона учитываются staged, unstaged и новые файлы; `--debt` использует прежнюю подтверждённую `.synced-dev`.

`--fix` меняет числа в исходниках: сначала проверьте формулы и полноту описаний. `--mark` закрывает общий диапазон долга: используйте только после действительной сверки всего диапазона и приёмки документов. Автоматически эти режимы не запускаются.

## Надёжность выпуска

PDF конвертируется в отдельный временный каталог с отдельным профилем LibreOffice. Существующий PDF заменяется только после успешной команды и проверки нового файла. Пустой результат или файл другого формата прерывают сборку. Ненайденные страницы оглавления, оставшиеся разрывы таблиц и изменение страниц после финальной вёрстки также останавливают выпуск.

Профиль LibreOffice создаётся в системном временном каталоге отдельно от папки документа: глубокий путь Windows может аварийно завершить конвертер ещё до создания PDF. Временный PDF остаётся на диске документа для атомарной замены. Ошибка содержит код завершения конвертера и признак наличия нового файла.

Проверка структуры не заменяет просмотр готовых страниц. Перед передачей проверьте оглавление, подписи, рисунки, переносы таблиц, кириллицу и метаданные. При неуспешной сборке файлы в каталоге нельзя считать новым принятым комплектом.

После успешной проверки создаётся файл `.build.json` документа: редакция, ревизия кода, число страниц и SHA-256 исходника, сборщика, DOCX и PDF. Перед публикацией сопоставьте хеши с файлами комплекта. Существование старого паспорта не доказывает успешность новой сборки.

Реквизиты клиентского экземпляра задаются локально: `DOC_HOLDER`, `DOC_HOLDER_SHORT`, `DOC_RECIPIENT`, `DOC_HANDOVER_DATE`. Не помещайте личные сведения и доступы в исходный код. Значения по умолчанию обезличены; их наличие не означает готовности экземпляра к передаче заказчику.

## Проверки инструментов

```sh
python -m unittest discover -s Документация/src -p test_doc_tools.py -v
```

Проверяются сбой команды, исчезновение факта, перенос списка моделей, имена с пробелами и отказ конвертера при старом PDF. Отдельные проверки охватывают продолжения длинных таблиц, запрет повторного выбора той же точки разрыва, завершающий бланк журнала и отличие заголовков основного текста от строк оглавления без точечного лидера. Эти проверки не запускают сайт, БД, контейнеры или массовую пересъёмку.

Для диагностики длительной сборки задайте `DOCS_DEBUG=1`: сборщик покажет обрабатываемую таблицу, страницу, точку разрыва и результат проверки. Это не отключает итоговую проверку и не разрешает публиковать файл после ошибки.

Обновление PDF в репозитории не заменяет файл, загруженный в раздел руководств приложения. Публикация в приложении и проверка скачивания выполняются отдельно в согласованном порядке.
