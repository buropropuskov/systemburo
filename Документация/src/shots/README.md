# Снимки экрана для руководств

Снимки для ролевых руководств снимаются автоматически: вручную их не пересоздать
одинаковыми, а руководств пять и кадров в них под двести.

## Что нужно поднять

Съёмка идёт с отдельного стенда, чтобы данные в кадре не зависели от того, что
кто-то успел завести руками, и чтобы наливка не попала в общую базу разработки.

1. Отдельная база и прикладной сервер на своём порту:

```
docker exec systemburo-db-1 psql -U postgres -c "CREATE DATABASE burodocs;"
docker run -d --name sbdocs-backend --network systemburo_default \
  -v <каталог рабочего дерева>:/app -v systemburo_go_mod_cache:/go/pkg/mod \
  -e DATABASE_URL="postgres://postgres:123@db/burodocs" \
  -e BIND_HOST=0.0.0.0 -e BIND_PORT=8095 \
  -e JWT_SECRET=... -e JWT_REFRESH_SECRET=... \
  -p 8095:8095 -w /app systemburo-go-backend sh -c "go run ./cmd/server"
```

2. Учётная запись администратора и вымышленные данные. Источник случайности
   фиксирован: пересъёмка обязана давать те же фамилии и номера, иначе картинки
   разойдутся с текстом.

```
docker exec sbdocs-backend sh -c "cd /app && go run ./cmd/seed admin123"
docker exec sbdocs-backend sh -c "cd /app && go run ./cmd/server fake -mark-stand"
docker exec sbdocs-backend sh -c "cd /app && go run ./cmd/server fake \
  -profile=medium -seed=19010811 -label=docs-shots -apply"
```

3. Донастройка: права охраннику на таблицы постов, список «по факту» и
   инструкция поста.

```
node Документация/src/shots/setup-stand.mjs
```

4. Веб-часть с проксированием на стенд:

```
cd frontend && VITE_API_TARGET=http://localhost:8095 npx vite --port 5199 --strictPort
```

## Съёмка

```
node Документация/src/shots/run.mjs --doc=user
node Документация/src/shots/run.mjs --doc=user --only=createapp-orginfo
```

Готовые файлы кладутся в `src/screenshots/<документ>/` и подставляются в текст
как `![Подпись](src/screenshots/user/createapp-orginfo.png)`. Номер рисунка
сборщик проставляет сам.

Прогон возвращает ненулевой код, если хоть один кадр дал предупреждение.
Предупреждения бывают двух видов, и оба означают брак, который иначе всплывёт
уже в собранном документе:

- кадр выше полутора ширин - картинка не поместится по высоте листа. Лечится
  раздельным воздухом по горизонтали (`"pad": {"x": 420, "y": 50}`) либо
  разбиением на два кадра;
- выноску некуда поставить, не задев соседей - кадру не хватает воздуха.

## Манифест

Файл `<документ>.json` рядом. Кадр описывается так:

```json
{
  "id": "createapp-orginfo",
  "role": "user",
  "goto": "/new-application",
  "waitFor": "[data-testid=\"ob-app-orginfo\"]",
  "prepare": [{ "click": "[data-testid=\"blank-add\"]" }, { "wait": "..." }],
  "clip": { "selector": "[data-testid=\"ob-app-orginfo\"]", "pad": 40 },
  "highlight": [
    { "selector": "#organization", "badge": 1 },
    { "selector": "#phoneNumber", "badge": 2 }
  ]
}
```

`role` - ключ из `accounts.json`. Действия подготовки: `click`, `fill`,
`select`, `press`, `hover`, `wait`, `waitHidden`, `scrollTo`.

Поля кадра:

| Поле | Смысл |
|---|---|
| `anon` | снимать до входа в систему (страница входа) |
| `role` | учётная запись из `accounts.json`, перекрывает роль манифеста |
| `clip.selector` | минимальная область кадра; обводимые элементы входят в неё всегда, даже если контейнер их не покрывает |
| `clip.pad` | воздух по краям: число либо `{x, y}` для узких высоких целей |
| `clip.full` | кадр во всё окно, для обзорных рисунков |
| `calm: false` | не убирать всплывшее перед подготовкой |

Поля цели обводки:

| Поле | Смысл |
|---|---|
| `selector`, `nth` | что обводим |
| `badge` | номер выноски; без него обводка без номера |
| `badgeInside` | номер садится на угол обводки, а не рядом с ней - для крупных областей, вокруг которых места нет |
| `inset` | линия уводится внутрь элемента - для областей, прижатых к краю окна, у которых наружная линия обрезалась бы кромкой |

Обводить надо тот элемент, который читатель видит как поле или кнопку. У поля
ввода это обёртка со значком и заливкой, а не сам `input`: у него своя
геометрия внутри обёртки, и линия по нему рассекает значок.

Проверочный манифест `probe.json` снимает три вида скругления - круг, пилюлю и
скруглённый прямоугольник. Прогонять после правок снимальщика.

## Почему сделано так

**Обводка рисуется отдельным слоем, а не правкой стилей элемента.** Правка
border или outline у самого элемента двигает соседей, и в кадр попадает уже не
та раскладка, которую видит работник.

**Радиусы берутся из вычисленных стилей и наращиваются на величину отступа.**
Наружная линия отстоит от элемента на постоянное расстояние, поэтому каждая
полуось скругления растёт ровно на отступ: круглая кнопка обводится кругом,
пилюля - пилюлей, прямой угол скругляется на величину отступа. Проценты в
радиусах разворачиваются в пиксели, иначе круглая кнопка обводится эллипсом.

**Выноска ставится мимо всех обведённых элементов, а не только мимо своего.**
В ряду соседних кнопок место «слева от третьей» - это ровно вторая кнопка.
Руководства прошлого поколения испорчены именно этим: кружки перекрывают
подписи пунктов меню и срезаны краем изображения.

**Снимок уменьшается до 1950 точек по ширине, но не увеличивается.** 1950 точек
при 300 ppi - это 16.5 см, ширина текста на листе. Мелкий кадр остаётся в своём
размере, и сборщик ставит его меньшей картинкой: растянутый на всю полосу, он
был бы размытым.

**Часы фиксируются подменой Date, но таймеры не останавливаются.** С
остановленными таймерами не догружаются списки и опрос уведомлений. Момент
берётся заведомо в прошлом относительно выдачи маркера доступа, иначе
приложение сочтёт его просроченным и выкинет на страницу входа.

**Каждой роли - своё окружение браузера, каждому кадру - своя вкладка.** Сеанс
продлевается по признаку в хранилище браузера, поэтому в общем окружении вход
второй учётной записи проходил бы поверх сеанса первой, и страница входа даже
не показывалась бы. Общая же вкладка тянет за собой состояние предыдущего
кадра - раскрытую панель, наведённый указатель, положение прокрутки; один кадр
из-за этого уже переставал сниматься в пачке, хотя в одиночку снимался.

**Уборка экрана идёт до подготовки кадра, а не после.** Она закрывает всплывшее
клавишей Esc, и после подготовки закрывала бы ровно то окно, ради которого кадр
и снимается.

**Перед съёмкой снимальщик ждёт, пока координаты целей перестанут меняться.**
Погашенных переходов мало: выезжающая панель на первом кадре ещё стоит за краем
окна со сдвигом, и признак «элемент виден» на ней уже верен. Снятая в этот
момент обводка легла бы мимо.
