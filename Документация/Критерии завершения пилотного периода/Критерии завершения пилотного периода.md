# 1. Общие сведения

## 1.1. Назначение документа

Документ устанавливает условия проведения пилотного периода системы электронной подачи заявок «Бюро пропусков» и перечень критериев, по которым принимается решение о переводе системы в промышленную эксплуатацию.

Документ отвечает на один вопрос: при каких условиях пилотный период считается пройденным. Все критерии сформулированы так, чтобы их выполнение можно было подтвердить фактом, а не мнением: пройденным сценарием, записью в журнале системы или измеренным показателем.

## 1.2. Область применения

Документ применяется на всём протяжении пилотного периода: при планировании, при ежедневной фиксации замечаний и при подведении итогов.

Порядок работы участников описан в руководствах пользователя, администратора и охранника. Порядок развёртывания и сопровождения системы описан в руководстве по развёртыванию и сопровождению. Настоящий документ их не повторяет.

## 1.3. Оформление

Сведения, требующие особого внимания, выделяются:

> ПРИМЕЧАНИЕ: пояснение, полезное для понимания.

> ВАЖНО: пропуск приведёт к неверной оценке результата пилотного периода.

# 2. Термины

Таблица: Термины, применяемые в документе

| Термин | Значение |
|---|---|
| Пилотный период | Ограниченная по сроку и охвату опытная эксплуатация системы на реальных данных силами штатных работников |
| Сценарий | Законченное действие пользователя, приводящее к проверяемому результату: например, подача заявки или отметка въезда |
| Обязательный сценарий | Сценарий, без успешного выполнения которого пилотный период не может быть признан пройденным |
| Дефект | Отклонение фактического поведения системы от ожидаемого, зафиксированное в журнале замечаний |
| Обходной путь | Способ получить нужный результат в обход дефекта, приемлемый по трудоёмкости |
| Рабочие часы | Период, в течение которого измеряются показатели доступности и времени отклика |
| Полный цикл заявки | Путь заявки от подачи до итогового решения с последующим отражением в таблице поста |

# 3. Условия проведения

## 3.1. Срок и охват

Таблица: Параметры пилотного периода

| Параметр | Значение |
|---|---|
| Длительность | 4 недели непрерывной эксплуатации |
| Охват по постам | Ограниченный круг постов, заполняется при согласовании |
| Охват по заявителям | Ограниченный круг работников и организаций, заполняется при согласовании |
| Данные | Реальные, вносимые в ходе обычной работы |
| Контур | Рабочий сервер, развёрнутый по руководству по развёртыванию |
| Дата начала | Заполняется при согласовании |
| Дата окончания | Заполняется при согласовании |

Длительность в четыре недели выбрана не произвольно. За этот срок гарантированно проходят все повторяющиеся циклы работы системы: суточный сброс территориальных статусов, недельные пики подачи заявок, обслуживание журнальных таблиц и полное обновление версии системы хотя бы один раз.

> ВАЖНО: пилотный период проводится на реальных данных. Внесённые в него заявки, реестры и справочники сохраняются и переходят в промышленную эксплуатацию, поэтому демонстрационное наполнение на этом контуре не применяется.

## 3.2. Состав участников

Таблица: Участники пилотного периода

| Роль в пилотном периоде | Кто выполняет | Задача |
|---|---|---|
| Заявители | Работники подразделений и представители организаций | Подача заявок в обычном рабочем порядке |
| Операторы бюро | Сотрудники бюро пропусков | Обработка заявок, ведение справочников и таблиц постов |
| Согласующие | Руководители, чьё решение требуется по заявкам | Согласование в своей зоне ответственности |
| Работники постов | Сотрудники охраны участвующих постов | Отметка прохода, проверка по чёрным спискам |
| Администратор системы | Сотрудник бюро с правами администратора | Учётные записи, права, разбор обращений |
| Сопровождение | Подразделение информационных технологий | Наблюдение за работой сервера, резервное копирование, сбор показателей |

Каждая роль должна быть задействована фактически. Пилотный период, в котором ни разу не выполнялось согласование или ни разу не отмечался проход, не даёт оснований для выводов о работоспособности системы.

## 3.3. Что фиксируется в ходе периода

- Замечания и отклонения — в журнале замечаний по форме приложения Б, в день обнаружения.
- Показатели работы системы — по журналу запросов, встроенному в систему; отдельные средства измерения не требуются.
- Выполнение обязательных сценариев — в перечне приложения А, отметкой ответственного.

# 4. Функциональные критерии

Критерий считается выполненным, если соответствующие обязательные сценарии выполнены на реальных данных и результат совпал с ожидаемым.

## 4.1. Подача и обработка заявок

Таблица: Критерии по обработке заявок

| Критерий | Как подтверждается |
|---|---|
| Заявка подаётся со всеми видами вложений | Поданы заявки, содержащие людей, транспорт и материальные ценности |
| Сведения повторно не вводятся | Выполнена подача с выбором ранее заведённых сотрудников и транспорта из реестра |
| Заявка проходит полный цикл | Не менее 50 заявок доведены от подачи до итогового решения |
| Согласование работает | Выполнено согласование с участием не менее двух согласующих по одной заявке |
| Отказ оформляется с причиной | Не менее одной заявки отклонено, причина видна заявителю |
| Отзыв заявки работает | Заявитель отозвал поданную заявку |
| Вопрос и ответ работают | По заявке задан вопрос заявителю и получен ответ без обращения по телефону |
| Пересылка работает | Заявка переслана целиком и отдельным вложением |
| Заявитель видит состояние | Заявитель определил текущий статус и историю заявки самостоятельно |

> ПРИМЕЧАНИЕ: порог в 50 заявок задан, чтобы выборка была представительной. При меньшем числе редкие сочетания условий не встретятся, и вывод о работоспособности будет преждевременным.

## 4.2. Чёрные списки

Таблица: Критерии по чёрным спискам

| Критерий | Как подтверждается |
|---|---|
| Точное совпадение не пропускается | Попытка подать заявку на лицо или транспорт из чёрного списка отклонена системой |
| Близкое совпадение выявляется | Заявка с изменённым написанием помечена признаком возможного совпадения |
| Согласование помеченной заявки заблокировано | Заявка с пометкой не согласуется, пока решение не принято явно |
| Решение пропустить фиксируется | В журнале видно, кто и когда разрешил пропуск вопреки запрету |

## 4.3. Работа постов

Таблица: Критерии по работе постов

| Критерий | Как подтверждается |
|---|---|
| Пост видит допущенные объекты | Одобренные объекты появились в таблице поста без участия администратора |

| Отметка видна другим постам | Изменение отражено на другом рабочем месте без перезагрузки страницы |

Таблица: Критерии по администрированию

| Поиск устойчив к раскладке | Запись найдена при вводе в неверной раскладке клавиатуры |

# 5. Наблюдаемые показатели работы

Показатели измеряются по журналу запросов, встроенному в систему. Отдельный нагрузочный стенд для этого не требуется.

Таблица: Наблюдаемые показатели

| Показатель | Допустимое значение | Способ измерения |
|---|---|---|
| Доля запросов, завершившихся ошибкой сервера | Не более 0,5 процента от общего числа за период | Журнал запросов, отбор по кодам ответа 500 и выше |
| Время отклика основных экранов | Не более 3 секунд для 95 процентов запросов | Журнал запросов, поле длительности |
| Время формирования отчёта | Не более 15 секунд | Журнал запросов по разделу аналитики |
| Доступность в рабочие часы | Не менее 99 процентов | Отсутствие периодов недоступности по журналу и обращениям |
| Незапланированные перезапуски | Отсутствуют | Журнал приложения на сервере |

> ПРИМЕЧАНИЕ: показатели названы наблюдаемыми, потому что снимаются в условиях реальной работы, а не на искусственной нагрузке. Подтверждение расчётной способности системы при 1000-1500 одновременно работающих пользователях выполняется отдельным нагрузочным испытанием и в задачи пилотного периода не входит.

# 6. Критерии по защите информации

Таблица: Критерии по защите информации

| Критерий | Как подтверждается |
|---|---|
| Работа ведётся по защищённому соединению | Обращение по незащищённому протоколу перенаправляется, предупреждений о сертификате нет |
| Доступ разграничен фактически | Попытка открыть чужой раздел завершилась отказом, отказ зафиксирован в журнале |
| Обращения к персональным данным учитываются | В журнале обращений к персональным данным видны записи за период с указанием работника и времени |
| Согласия фиксируются | По поданным заявкам зафиксированы согласия на обработку персональных данных |
| Пароли не раскрываются | Пароли отсутствуют в журналах системы и сервера |

# 7. Критерии по эксплуатации

Проверяется не только работа системы, но и способность подразделения информационных технологий её сопровождать.

Таблица: Критерии по эксплуатации

| Критерий | Как подтверждается |
|---|---|
| Резервная копия создаётся | Копия базы данных и загруженных файлов создана по установленному порядку |
| Восстановление проверено | Выполнено пробное восстановление копии, данные читаются |
| Обновление версии выполнено | Проведено обновление системы с сохранением данных |
| Состояние контролируется | Настроено наблюдение за состоянием служб и свободным местом |
| Журналы читаются | Специалист самостоятельно нашёл в журнале причину обращения пользователя |

> ВАЖНО: восстановление из резервной копии проверяется фактически. Настроенное, но ни разу не проверенное копирование резервной копией не является.

# 8. Учёт замечаний

## 8.1. Классификация

Таблица: Уровни замечаний

| Уровень | Признак | Пример |
|---|---|---|
| Блокирующий | Работа невозможна, обходного пути нет | Не выполняется вход в систему, заявка не отправляется |
| Критический | Ключевая функция не работает, обходной путь несоразмерно трудоёмок | Не формируется печатная форма, пост не видит одобренные объекты |
| Значительный | Функция работает неверно, но обходной путь приемлем | Неверная сортировка списка, ошибка в подписи столбца выгрузки |
| Незначительный | Не влияет на результат работы | Опечатка в подсказке, смещение элемента интерфейса |

Уровень присваивается при регистрации замечания и может быть пересмотрен по согласованию сторон.

## 8.2. Порядок регистрации

Замечание регистрируется в журнале по форме приложения Б в день обнаружения. Обязательно указываются: что делал работник, что ожидал получить, что получил фактически, время и роль. Без этих сведений замечание невоспроизводимо и к учёту не принимается.

# 9. Условия успешного завершения

Пилотный период считается успешно завершённым при одновременном выполнении всех условий.

Таблица: Сводные условия успешного завершения

| № | Условие |
|---|---|
| 1 | Период отработан полностью, без остановки эксплуатации по причине неработоспособности системы |
| 2 | Все обязательные сценарии приложения А выполнены, каждый подтверждён отметкой ответственного |
| 3 | Не осталось незакрытых блокирующих замечаний |
| 4 | Не осталось незакрытых критических замечаний |
| 5 | По каждому незакрытому значительному замечанию согласован срок устранения |
| 6 | Наблюдаемые показатели раздела 5 находятся в допустимых пределах |
| 7 | Выполнены все критерии по защите информации раздела 6 |
| 8 | Выполнены все критерии по эксплуатации раздела 7 |
| 9 | Задействованы все роли участников, включая согласующих и работников постов |
| 10 | Не менее 50 заявок прошли полный цикл |

Незначительные замечания на решение о завершении не влияют и переносятся в план последующих доработок.

> ВАЖНО: условия 3 и 4 не допускают исключений. Замечание уровня «блокирующий» или «критический», по которому согласован лишь срок устранения, считается незакрытым.

# 10. Порядок принятия решения

По окончании периода стороны рассматривают: заполненный перечень обязательных сценариев, журнал замечаний с текущими состояниями, сводку наблюдаемых показателей.

Возможны три решения.

**Пилотный период пройден.** Все условия раздела 9 выполнены. Система переводится в промышленную эксплуатацию, охват расширяется на остальные посты и подразделения.

**Пилотный период продлевается.** Условия не выполнены, но причина устранима в короткий срок. Указываются перечень невыполненных условий, срок продления и лицо, ответственное за устранение. Повторное подведение итогов проводится по тем же критериям.

**Пилотный период не пройден.** Выявлены замечания, устранение которых требует существенной переработки. Оформляется перечень необходимых изменений и назначается новый пилотный период после их внесения.

Решение оформляется протоколом по форме приложения В.
