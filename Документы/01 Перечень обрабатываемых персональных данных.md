# Перечень обрабатываемых персональных данных

Документ описывает, какие персональные данные обрабатывает система бюро пропусков,
у каких категорий субъектов они собираются, где хранятся и как защищены. Составлен
по фактическому устройству базы данных, а не по замыслу: каждая строка проверена по
описанию таблиц в исходном коде.

Документ служит исходными данными для приказа об утверждении перечня обрабатываемых
персональных данных, для уведомления в Роскомнадзор и для определения уровня
защищённости информационной системы. Правовые формулировки, цели обработки и сроки,
установленные организацией, вносит оператор.

## 1. Категории субъектов

| Категория | Кто это | Как данные попадают в систему |
|---|---|---|
| Работники организации-оператора | Сотрудники бюро пропусков, охранники постов, администраторы | Заводит администратор при создании учётной записи |
| Работники организаций-заявителей | Те, кто подаёт и согласовывает заявки | Заводит администратор или ответственный своей организации |
| Посетители и работники подрядчиков | Люди, на которых оформляется пропуск | Вносит заявитель при подаче заявки, либо массово из бланка |
| Водители и владельцы транспорта | Лица, чьи автомобили въезжают на территорию | Вносит заявитель в составе заявки |

Первые две категории имеют учётную запись и работают в системе. Третья и четвёртая
учётной записи не имеют, их данные вносит третье лицо, поэтому согласие на обработку
подтверждает заявитель, а система фиксирует факт подтверждения.

## 2. Состав данных

### 2.1. Учётные записи работников

Таблица `users`.

| Данные | Хранение |
|---|---|
| Имя учётной записи | Открыто, уникальный указатель |
| Фамилия, имя, отчество | Открыто |
| Должность | Открыто |
| Адрес электронной почты | Открыто |
| Номер телефона | Открыто |
| Организация и подразделение | Ссылками на справочники |
| Пароль | Только необратимая свёртка Argon2id, исходный пароль не хранится |
| Время последнего входа и последней активности | Открыто |
| Признаки блокировки, причина блокировки, история блокировок | Открыто |

Сопутствующие таблицы: история изменений учётной записи, история блокировок, ранее
использованные пароли (только свёртки, для запрета повторного использования).

### 2.2. Участники заявок

Таблицы `employees` (строки заявок) и `unique_employees` (реестр ранее заведённых лиц).

| Данные | Хранение |
|---|---|
| Фамилия, имя, отчество | Открыто |
| Гражданство | Ссылкой на справочник |
| Должность | Открыто |
| Серия и номер паспорта | Зашифровано AES-256-GCM; для поиска отдельно хранится необратимая свёртка HMAC-SHA256 |
| Номер патента | Зашифровано тем же способом, со своей свёрткой для поиска |
| Иное разрешение на работу | Открыто |
| Время въезда на территорию и выезда | Открыто |
| Отметка о согласии субъекта: время и кто подтвердил | Открыто |

Открытого значения паспорта и патента в базе нет. Свёртка для поиска необратима:
она позволяет найти совпадение по точному значению, но не восстановить его.

### 2.3. Транспортные средства

Таблицы `cars` и `unique_cars`.

| Данные | Хранение |
|---|---|
| Государственный регистрационный знак | Открыто |
| Марка | Открыто |
| Организация и подразделение владельца | Ссылками на справочники |
| Места разгрузки, планируемое время, примечания | Открыто |
| Время въезда и выезда | Открыто |
| Отметка о согласии субъекта | Открыто |

### 2.4. Заявки

Таблица `applications`.

| Данные | Хранение |
|---|---|
| Текст заявки | Открыто |
| Имя инициатора | Открыто |
| Контактный телефон | Открыто |
| Кто подал, кто ведёт, кто согласует | Ссылками на учётные записи |
| Комментарии ответственного и решения согласующих | Открыто |
| Даты подачи, прочтения, согласования, завершения | Открыто |

Сопутствующие таблицы: вопросы к заявке и ответы на них, дополнения к заявке,
история изменения состояния, отметки о прочтении.

### 2.5. Файлы

Таблицы `application_files`, `documents`, выгрузки бланков.

| Данные | Хранение |
|---|---|
| Файлы, приложенные к заявке | На диске сервера, зашифрованы возрастной схемой age |
| Сформированные бланки пропусков | На диске сервера, шифрование включается ключами архива |
| Имя файла, тип, размер, кто загрузил | В базе открыто |

Содержимое приложенных файлов задаёт заявитель, поэтому состав данных в них
не ограничен системой: там могут быть копии документов, удостоверяющих личность.

### 2.6. Чёрные списки

Таблица `blacklist`. Государственный регистрационный знак либо фамилия, имя,
отчество, отметка о причине и признак действия. Хранится открыто.

### 2.7. Журналы

| Журнал | Что записывается | Таблица |
|---|---|---|
| Обращения к персональным данным | Кто, какое действие, к какому разделу и записи, сетевой адрес, метод, путь запроса, код ответа, время | `pd_audit_logs` |
| События входа | Успешные и неудачные попытки, блокировки | `auth_events` |
| Журнал запросов | Обращения к программному интерфейсу | `request_logs`, разбит по суткам |
| История сущностей | Кто и что менял в заявках, справочниках, учётных записях | `audit_log` и таблицы истории |
| Согласия | Вид согласия, редакция текста, контрольная сумма текста, сетевой адрес, сведения о браузере, время подтверждения и отзыва | `consents` |

Сетевой адрес и сведения о браузере в журналах относятся к персональным данным
и учитываются в перечне наравне с прочими сведениями.

## 3. Что система не собирает

Специальные категории персональных данных по статье 10 закона (состояние здоровья,
религиозные и политические взгляды, судимость) система не запрашивает и полей под
них не имеет. Биометрические данные не обрабатываются: фотографий лиц в составе
данных участника нет, распознавание не применяется. Гражданство собирается как
сведение о документе, дающем право на работу, и специальной категорией не является.

Оговорка: содержимое произвольно приложенных к заявке файлов система не
контролирует, и заявитель технически может приложить документ с иными сведениями.
Порядок работы с такими приложениями определяет оператор.

## 4. Места хранения

| Где | Что лежит | Защита |
|---|---|---|
| База данных PostgreSQL | Все таблицы выше | Доступ только из внутренней сети контейнеров, наружу порт не публикуется |
| Диск сервера, каталог загрузок | Файлы, приложенные к заявкам | Шифрование age |
| Диск сервера, каталог архива бланков | Сформированные бланки | Шифрование включается ключами архива |
| Резервные копии | Выгрузка базы и архив файлов | Шифрование обязательно, снятие копии без ключа не выполняется |

Ключ шифрования персональных данных в резервную копию намеренно не включается и
хранится отдельно, в хранилище секретов организации.

## 5. Передача данных

Система не передаёт персональные данные третьим лицам для обработки и не обращается
к внешним сервисам за их обработкой. Наружу уходят два потока.

Письма отправляются на адреса работников через почтовый сервер, указанный оператором.
В письме передаются имя учётной записи, обращение по имени, адрес системы и служебные
сведения о заявке. Пароль в письме передаётся только при выдаче временного, и он
подлежит смене при первом входе. Отправка выключается пустым адресом почтового сервера,
и тогда этот поток отсутствует вовсе.

Уведомления в браузер идут через службу доставки, которую определяет сам браузер
пользователя (Google для Chrome, Mozilla для Firefox). Содержимое уведомления
шифруется ключами конкретной подписки по стандарту Web Push, поэтому служба доставки
видит только адрес подписки и факт отправки, но не текст. Служба находится за пределами
Российской Федерации, и оператору следует учесть это при оценке потоков: сами
персональные данные ей не раскрываются, но факт обращения к иностранному сервису есть.
Push-уведомления отключаются, если оператор сочтёт это нежелательным.

Трансграничная передача не осуществляется.
