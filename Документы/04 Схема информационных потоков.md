# Схема информационных потоков

Документ описывает, откуда персональные данные приходят в систему, где хранятся,
кто их читает и куда они уходят. Нужен для определения уровня защищённости
информационной системы и построения модели угроз.

## 1. Состав системы

Система разворачивается на одном сервере и состоит из четырёх частей, работающих
в изолированной сети контейнеров.

```
       интернет / сеть организации
                  |
                  | TLS, порты 80 и 443
                  v
        +---------------------+
        |    веб-сервер       |  единственная часть, доступная снаружи
        +---------------------+
           |               |
           | статика       | обращения к интерфейсу
           v               v
   +-------------+   +------------------+
   | веб-часть   |   | сервер приложения |
   +-------------+   +------------------+
                          |         |
                          |         +--> диск сервера: файлы заявок,
                          |              архив бланков (зашифрованы)
                          v
                  +----------------+
                  | база данных    |  порт наружу не публикуется
                  +----------------+
```

## 2. Откуда данные приходят

| Источник | Что вносится | Кто вносит |
|---|---|---|
| Форма подачи заявки | Сведения об участниках и транспорте, контакты | Работник организации-заявителя |
| Массовый ввод из бланка | Те же сведения из файла электронной таблицы | Работник организации-заявителя |
| Карточка учётной записи | Данные работника системы | Администратор |
| Реестры людей и машин | Ранее заведённые сведения, повторно используемые | Работник или администратор |
| Посты охраны | Отметки о проходе и въезде | Охранник |
| Приложенные файлы | Произвольные документы | Работник организации-заявителя |

Данные вводятся людьми через интерфейс. Автоматической загрузки из внешних систем
и обмена с другими информационными системами нет.

## 3. Где хранятся

| Хранилище | Содержимое | Расположение |
|---|---|---|
| База данных | Учётные записи, заявки, участники, транспорт, справочники, журналы, согласия | Том на диске сервера |
| Каталог загрузок | Файлы, приложенные к заявкам | Диск сервера, шифрование age |
| Каталог архива | Сформированные бланки пропусков | Диск сервера, шифрование по ключам архива |
| Каталог копий | Резервные копии базы и файлов | Диск сервера, шифрование обязательно |

За пределы сервера данные не выносятся, за исключением выгрузок, которые работник
скачивает себе, и потоков, перечисленных ниже.

## 4. Кто читает

| Кто | Что видит |
|---|---|
| Заявитель | Свои заявки и заявки своей организации, свои справочники |
| Согласующий | Заявки, где требуется его решение |
| Принимающий | Заявки, взятые в работу, и очередь бюро |
| Охранник поста | Таблицы своего поста: кто и на чём проходит сегодня |
| Администратор | Учётные записи, права, справочники, журналы, аудит обращений |
| Супер-администратор | Всё, включая настройку прав |

Каждое обращение к разделам с персональными данными записывается в журнал учёта
обращений.

## 5. Куда уходят

| Поток | Что уходит | Куда | Управление |
|---|---|---|---|
| Электронная почта | Имя учётной записи, обращение по имени, адрес системы, сведения о заявке, временный пароль при выдаче | Почтовый сервер, указанный оператором | Отключается пустым адресом сервера |
| Уведомления в браузер | Текст извещения, зашифрованный ключами подписки | Служба доставки браузера пользователя, за пределами страны | Отключается, работает только с согласия пользователя на уведомления |
| Выгрузки | Списки участников, бланки, отчёты в форматах электронных таблиц и PDF | На устройство работника, по его действию | Закрыто отдельным правом, каждое скачивание записывается в журнал |
| Резервные копии | Полный состав базы и файлов | Внешнее хранилище, если оператор его настроил | Шифрование обязательно |

Есть ещё один поток, не относящийся к персональным данным, но подлежащий учёту.
Страница системы подключает шрифты со стороннего источника (`fonts.googleapis.com`
и `fonts.gstatic.com`), поэтому браузер каждого пользователя обращается к нему
напрямую. Персональные данные в этом запросе не передаются, но сетевой адрес
пользователя и сведения о браузере становятся известны владельцу источника, который
находится за пределами Российской Федерации. Кроме того, при отсутствии выхода
в интернет на рабочих местах шрифты не загрузятся и вид страниц изменится.
Поток устраняется размещением шрифтов на самом сервере; оператору следует решить,
требуется ли это в его контуре.

Иных исходящих потоков нет: система не обращается к внешним сервисам за обработкой
данных, не использует внешнюю аналитику и не подключает сторонние сценарии
на страницах.

## 6. Точки, требующие внимания оператора

1. Файлы, приложенные к заявке, система по содержимому не проверяет. Порядок работы
   с ними определяет оператор.
2. Выгрузки покидают контур и дальше живут на устройстве работника. Ограничение
   круга допущенных к выгрузке остаётся организационной мерой.
3. Служба доставки уведомлений в браузер находится за пределами Российской Федерации.
   Содержимого она не видит, но обращение к ней есть, и его следует отразить в модели
   угроз либо отключить уведомления.
4. Шрифты загружаются со стороннего источника за пределами страны. Устраняется
   размещением шрифтов на сервере системы.
5. Резервные копии содержат полный состав данных. Место их хранения и круг лиц,
   имеющих к ним доступ, определяет оператор.
